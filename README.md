# ربات تلگرام مدیریت VPS

با `/start` منوی دکمه‌های شیشه‌ای باز می‌شود. دسترسی به گفت‌وگوی خصوصی و شناسه‌های عددی ادمین محدود است.

- **SSH** یک اتصال باز می‌کند و هر پیام را به‌عنوان یک دستور مستقل، بدون ترمینال تعاملی، اجرا می‌کند. برای بستن اتصال از `/cancel` استفاده کن. اتصال بعد از ۱۰ دقیقه منقضی می‌شود.
- **نصب نود پاسارگارد** نصب‌کنندهٔ رسمی را با `install -y` و پیش‌فرض‌های آن اجرا می‌کند. پس از موفقیت، کلید API و گواهی عمومی PEM را جداگانه به‌شکل متن کپی‌شونده می‌فرستد. اگر مسیر نصب یا دادهٔ قبلی وجود داشته باشد، عملیات را متوقف می‌کند.
- **UFW** در حالت روشن‌کردن ابتدا دسترسی TCP به پورت SSH همین اتصال را مجاز می‌کند. هر دو دکمه وضعیت نهایی UFW را نشان می‌دهند.
- **`/update`** از شاخهٔ پیگیری‌شده در `origin` نسخه می‌گیرد، فقط fast-forward را می‌پذیرد و پس از تغییر کد به systemd اجازه می‌دهد فرایند را دوباره اجرا کند.

## راه‌اندازی روی Debian یا Ubuntu

روی میزبان ربات Python 3.10 یا جدیدتر، Git و systemd لازم است. اگر مخزن را خصوصی کردی، برای حساب سرویس یک کلید deploy فقط‌خواندنی در GitHub تنظیم کن و در دستور clone از آدرس SSH مخزن استفاده کن. کلید میزبان GitHub باید در `known_hosts` حساب سرویس تأیید شده باشد. این کلید با کلید اتصال به VPSها جداست.

```bash
sudo apt update
sudo apt install -y git python3 python3-venv
sudo useradd --system --create-home --home-dir /var/lib/telegram-vps --shell /usr/sbin/nologin telegram-vps
sudo install -d -o telegram-vps -g telegram-vps /opt/telegram-vps-bot
sudo -u telegram-vps -H git clone https://github.com/ramin346/telegram-vps-bot.git /opt/telegram-vps-bot
sudo -u telegram-vps -H python3 -m venv /opt/telegram-vps-bot/.venv
sudo install -m 600 /dev/null /etc/telegram-vps-bot.env
sudoedit /etc/telegram-vps-bot.env
```

در فایل تنظیمات توکن BotFather و شناسهٔ عددی تلگرام خودت را بگذار. برای چند ادمین شناسه‌ها را با کاما جدا کن. خط `SSH_KEY_PATH` اختیاری است. اگر آن را می‌گذاری، کلید خصوصی مخصوص VPS باید برای کاربر سرویس خواندنی باشد و کلید عمومی آن روی سرورهای مقصد ثبت شده باشد.

```ini
TELEGRAM_BOT_TOKEN=botfather-token
TELEGRAM_ADMIN_IDS=123456789
ENABLE_UPDATE=1
SSH_KEY_PATH=/var/lib/telegram-vps/.ssh/id_vps
```

```bash
sudo install -m 644 /opt/telegram-vps-bot/telegram-vps-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now telegram-vps-bot
sudo journalctl -u telegram-vps-bot -n 30
```

## اتصال به VPS

بعد از انتخاب دکمه، ربات به‌ترتیب **آی‌پی یا آدرس سرور**، **نام کاربری** و **رمز SSH** را در سه پیام جداگانه می‌پرسد. پورت پیش‌فرض ۲۲ است. برای پورت سفارشی از `vps.example.com:2222` یا `[IPv6]:2222` استفاده کن. اگر کلید ورود SSH را تنظیم کرده‌ای، در مرحلهٔ رمز می‌توانی یک نقطه بفرستی.

ربات کلیدهای ثبت‌شده در `~/.ssh/known_hosts` کاربر سرویس را بررسی می‌کند. برای سرور جدید، کلید اعلام‌شده از طرف سرور را در اولین اتصال موفق، بدون سؤال، در `~/.ssh/telegram-vps-known-hosts` ثبت می‌کند. اگر کلید ثبت‌شده تغییر کند، اتصال رد می‌شود. برای بررسی هویت سرور از همان اتصال اول، کلید تأییدشدهٔ آن را از قبل در `known_hosts` قرار بده.

ربات تلاش می‌کند پیام رمز را حذف کند. چت ربات تلگرام رمزنگاری سرتاسری ندارد و کلید API در تاریخچهٔ چت می‌ماند. نصب و عملیات UFW نیاز به دسترسی root یا sudo بدون سؤال رمز دارند. نصب‌کننده روی مقصد به Bash، curl، flock و دسترسی اینترنت نیاز دارد.

## افزودن ادمین از داخل تلگرام

ادمین‌های اصلی همان شناسه‌های `TELEGRAM_ADMIN_IDS` هستند. در چت خصوصی ربات، از منوی `/start` روی «افزودن ادمین» بزن و آیدی عددی کاربر را بفرست. برای افزودن با نام کاربری، نام کاربر را در انتخاب‌گر تلگرام جست‌وجو و حساب را انتخاب کن. اگر ابتدا نام کاربری را در چت تایپ کنی، ربات تطابق حساب انتخاب‌شده را هم بررسی می‌کند.

کاربر اضافه‌شده با `/start` به SSH، نصب پاسارگارد و UFW دسترسی دارد و اطلاعات ورود SSH خودش را وارد می‌کند. افزودن ادمین، `/update` و استفاده از کلید SSH میزبان ربات مخصوص ادمین‌های اصلی است. آیدی‌های اضافه‌شده در پایگاه SQLite کاربر سرویس در `~/.local/share/telegram-vps-bot/admins.sqlite3` ذخیره می‌شوند و بعد از ری‌استارت و آپدیت باقی می‌مانند.

## سرورهای من

بعد از هر ورود موفق با اطلاعات تازه، ربات آدرس، پورت، نام کاربری و روش ورود را برای همان حساب تلگرام ذخیره می‌کند. دفعهٔ بعد، بعد از انتخاب SSH، پاسارگارد یا UFW از فهرست سرور را انتخاب کن. برای اتصال مستقیم SSH یا حذف ورودی، از منوی «سرورهای من» سرور را باز کن و دکمهٔ مربوطه را بزن. حذف ورودی فقط اطلاعات ذخیره‌شده در ربات را پاک می‌کند. اگر رمز عوض شده باشد، ربات پس از ناموفق بودن ورود با رمز ذخیره‌شده، رمز تازه را می‌پرسد.

رمزها در فایل پایگاه دادهٔ کاربر سرویس رمزگذاری می‌شوند. کلید رمزگذاری در `~/.local/share/telegram-vps-bot/servers.key` با دسترسی محدود به کاربر سرویس نگه داشته می‌شود. برای مهاجرت، از گزینهٔ «پشتیبان‌گیری و بازیابی» استفاده کن.

## ساخت سرور کاماترا

این منو فقط برای شناسه‌های ادمین اصلی فعال است. از `/start` وارد «سرور کاماترا» شو و در «ثبت یا تعویض کلید API»، اول Access Key و بعد Secret Key مربوط به API سرور کاماترا را بفرست. API مقدار Access Key را در فیلد `clientId` و مقدار Secret Key را در فیلد `secret` می‌گیرد. کلیدهای Object Storage برای این بخش کاربرد ندارند. کلید پس از احراز هویت، برای حساب تلگرام خودت در SQLite و با کلید رمزگذاری موجود ربات ذخیره می‌شود. ربات تلاش می‌کند پیام حاوی کلید را حذف کند.

در «ساخت VPS»، دیتاسنتر، ایمیج، CPU، رم و دیسک را مرحله‌به‌مرحله با دکمه‌های شیشه‌ای انتخاب کن. فقط نام و رمز اولیهٔ سرور را تایپ کن. این مسیر یک سرور با تعرفهٔ ساعتی، IP عمومی، روشن‌شدن خودکار و بدون سرویس مدیریت یا بکاپ روزانه درخواست می‌دهد. درخواست فقط پس از زدن «تأیید ساخت و هزینه» فرستاده می‌شود. برای بررسی نتیجه از «وضعیت آخرین درخواست» استفاده کن. اگر هنگام ارسال نتیجه نامشخص بود، صف عملیات پنل را قبل از درخواست مجدد بررسی کن.

[مستندات رسمی API کاماترا](https://console.kamatera.com/docs)

در «سرور کاماترا → سرورهای موجود» می‌توانی VPSهای حساب متصل را ببینی و وضعیت روشن یا خاموش، دیتاسنتر، آدرس‌های شبکه، دیسک و نوع تعرفهٔ هر VPS را بررسی کنی. برای روشن‌کردن، خاموش‌کردن یا ری‌استارت، سرور و عملیات را انتخاب کن و سپس تأیید بزن. پس از پذیرش درخواست توسط کاماترا، «وضعیت عملیات» نتیجه را از صف کاماترا می‌خواند.

## ساخت و مدیریت VPS در Linode

در منوی ادمین اصلی، «سرور Linode» را باز کن. یک Personal Access Token با دسترسی `Linodes: Read/Write` ثبت کن. توکن برای همان ادمین رمزگذاری می‌شود و ربات تلاش می‌کند پیام حاوی توکن را حذف کند.

برای ساخت، منطقه، ایمیج عمومی و پلن موجود را از دکمه‌ها انتخاب کن و نام و رمز قوی root را وارد کن. قیمت ساعتی و ماهانهٔ اعلام‌شده برای آن منطقه قبل از تأیید نمایش داده می‌شود. در «سرورهای موجود»، وضعیت، IP، منطقه و پلن هر VPS نمایش داده می‌شود. روشن‌کردن، خاموش‌کردن و ری‌استارت نیاز به تأیید دارند و می‌توانی بعد از ارسال درخواست، وضعیت را تازه‌سازی کنی.

[مستندات رسمی API لینود](https://techdocs.akamai.com/linode-api/reference/post-linode-instance)

برای حذف VPS، از «سرورهای موجود» وارد جزئیات سرور شو و «حذف سرور» را بزن. ربات نام و شناسهٔ سرور را قبل از تأیید نشان می‌دهد. تأیید، خود VPS و داده‌های روی آن را برای همیشه از Linode حذف می‌کند.

## ساخت و مدیریت VPS در Hetzner Cloud

ادمین اصلی می‌تواند از «سرور هتزنر» توکن API پروژه با دسترسی `Read & Write` را ثبت کند. توکن برای همان حساب تلگرام رمزگذاری و ذخیره می‌شود. برای ساخت VPS، لوکیشن، پلن، ایمیج و کلید SSH پروژه را با دکمه‌های شیشه‌ای انتخاب کن و نام سرور را بفرست. اگر «بدون کلید SSH» را انتخاب کنی، ربات رمز اولیهٔ root را که هتزنر تولید می‌کند در چت خصوصی نشان می‌دهد. قیمت ساعتی و ماهانهٔ پلن با مالیات پیش از تأیید نمایش داده می‌شود. هزینهٔ IPv4 عمومی جداست.

«سرورهای موجود» فهرست VPSهای پروژه را با وضعیت، IP، لوکیشن و پلن نشان می‌دهد. روشن‌کردن، خاموش‌کردن، ری‌استارت و حذف دائمی نیاز به تأیید دارند. اگر محافظت در برابر حذف فعال باشد، دکمهٔ حذف نمایش داده نمی‌شود.

[مستندات رسمی Hetzner Cloud API](https://docs.hetzner.cloud/reference/cloud)

برای بازنشانی رمز، پس از ساخت یا از جزئیات VPS روی «بازنشانی رمز root» بزن و تأیید کن. ربات از API رسمی Reset Password هتزنر استفاده می‌کند و رمز جدید تولیدشده را به‌صورت متن قابل کپی در چت خصوصی نشان می‌دهد. اگر عملیات هنوز در جریان باشد، از «بررسی وضعیت بازنشانی» نتیجه را بگیر.

### چند حساب یا پروژهٔ هتزنر

مسیر «سرور هتزنر ← افزودن حساب» را باز کن، یک نام مثل «شخصی» یا «کاری» بفرست و توکن پروژه را ثبت کن. در فهرست هتزنر اول حساب را انتخاب کن. ساخت VPS، سرورهای موجود، عملیات مدیریت و بازنشانی رمز root همگی با توکن همان حساب انجام می‌شوند. برای تعویض توکن، وارد همان حساب شو و «تعویض توکن همین حساب» را بزن. حساب‌ها فقط برای ادمین ثبت‌کننده نمایش داده می‌شوند. توکن نسخهٔ قبلی خودکار با نام «پیش‌فرض» منتقل می‌شود.

## مدیریت ساب‌دامنه‌ها در Cloudflare

با حساب ادمین اصلی وارد «Cloudflare» شو و API Token را ثبت کن. توکن به **Zone Read** و **DNS Edit** برای دامنه‌های موردنظر نیاز دارد و به‌صورت رمزگذاری‌شده ذخیره می‌شود. سپس در «مدیریت DNS» دامنه را انتخاب کن.

فهرست و جست‌وجو رکوردهای ساب‌دامنهٔ آن دامنه را نمایش می‌دهند. برای افزودن یا تغییر نام، مقصد، Proxy و TTL، از رکوردهای A، AAAA و CNAME استفاده کن. TTL رکوردهای دارای Proxy روی حالت خودکار است. حذف رکورد از صفحهٔ جزئیات انجام می‌شود. ساخت، ویرایش و حذف در Cloudflare فقط بعد از تأیید انجام می‌شوند.

## انتقال دیتابیس به VPS جدید

1. روی ربات فعلی با حساب ادمین اصلی از «پشتیبان‌گیری و بازیابی» روی «دریافت فایل پشتیبان» بزن. یک عبارت عبور قوی (حداقل ۱۲ کاراکتر) بفرست و فایل `.tvps` و عبارت عبور را جداگانه نگه دار.
2. همین نسخه یا نسخهٔ سازگار ربات را روی VPS جدید نصب کن. توکن BotFather و شناسه‌های ادمین اصلی (`TELEGRAM_ADMIN_IDS`) را در تنظیمات سرویس وارد کن. اگر همان توکن BotFather را استفاده می‌کنی، قبل از اجرای ربات روی میزبان جدید، سرویس قدیمی را متوقف کن.
3. از ربات جدید «بازیابی از فایل» را انتخاب کن، فایل و همان عبارت عبور را بفرست و بعد از بررسی تعداد موارد، جایگزینی را تأیید کن.

فایل شامل سرورهای ذخیره‌شده، ادمین‌های اضافه‌شده و حساب‌ها و توکن‌های سرویس‌های ابری است. هنگام بازیابی، اطلاعات محرمانه با کلید محلی VPS جدید رمزگذاری می‌شوند. فایل تنظیمات سرویس، کلید خصوصی SSH و فایل کلیدهای میزبان SSH خارج از دیتابیس‌اند و باید جداگانه منتقل شوند.
